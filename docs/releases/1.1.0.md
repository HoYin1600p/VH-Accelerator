# VH Accelerator 1.1.0 — critical update

Release status: **prepared locally; not published**.

Version 1.1.0 is a major client launch, memory, and compatibility update. It
defers work that does not have to complete before the main menu, keeps dynamic
and custom models on guarded paths, and corrects several recipe-cache and
world-transition problems. This release is classified as **critical** so the
in-game updater will notify users who keep critical-only notices enabled.

## Download and compatibility

The release artifact will be `VH-Accelerator-1.1.0.jar` for Minecraft 1.18.2
and Forge 40.3.11 or later in the Forge 40.x line. Do not install a sources JAR.

One JAR retains the existing Vault Hunters Remastered, official VH3, custom MVP,
JEI 9 and JEI 10 compatibility paths. The tested Wolds Vaults baseline now
includes 0.34.1 with The Vault `3.21.6.6884`. VHA is intended for both clients
and dedicated servers, but dedicated-server behavior has not yet been tested.

## Main improvements

- Eligible plain-JSON item and block-state models can finish baking when first
  needed. After one certification launch, warm launches can also skip loading
  eligible block-state graphs until first use. Generated, CTM-wrapped, Vault
  gear, custom-geometry and other dynamic models retain compatibility guards.
- Model-bake-event handling no longer forces unrelated deferred models at
  launch. CTM metadata prefetching, indexed KubeJS pack lookups and the
  resource-pack index reduce repeated atlas-preparation work.
- Version-gated Decocraft and Every Compat caches avoid repeated generation
  and parsing. Compact FerriteCore property views and baked-model face lists
  reduce memory where the supported versions are installed; Vault Render
  Optimization retains ownership of overlapping fixes.
- JEI's recipe index uses less menu memory, restores eligible plans across
  sessions, and starts its synchronized recipe fingerprint earlier during
  world join. CraftTweaker, KubeJS, Create and Vault recipe paths gain guarded
  indexing or parallel matching where the tested versions permit it.
- Several Wolds 0.34.1 warm-launch measurements improved from about 52 seconds
  at the start of this development pass to about 44 seconds after the atlas
  changes. Results vary by pack, hardware, installed mods and cache state;
  this is not a universal 8-second claim.

## Correctness and memory fixes

- Fixed persistent JEI cache reuse with randomized recipe outputs and large
  ingredient groups. Cached recipes still undergo live output and category
  checks; changed server tags and recipes continue to invalidate the cache.
- Prevented two chunk workers from seeing a half-loaded deferred block graph.
  CTM's render-layer pass now bakes only deferred models it actually wraps.
- Corrected optional compatibility preflight for unsupported mod layouts,
  null top-level model bakes, and a failed JEI search-index fallback.
- JER's singleplayer loot data is rebuilt per world, and its display entities
  are released on logout. After a stopped integrated world, guarded cleanup
  releases obsolete world references retained by cooperating mod caches.
- A new first-run default migration enables the 1.1.0 model settings for
  existing configurations once while preserving changes made afterward.

## Additional guarded optimizations

- Forge registry and ingredient validation, ModWorkManager wakeups, voxel
  shapes, entity-model cubes, GeckoLib resources and resource-location storage
  received targeted improvements.
- Integrated singleplayer loading gains background chunk disk reads and a
  brief server-tick hold while the first join packet is processed. Vault cake
  modifiers, cascade filters and modifier lists avoid repeated scans in the
  compatible singleplayer Vault builds.
- Debug diagnostics gained phase timing, model-bake counts and compatibility
  preflight reports. Normal launches still keep diagnostic-only mixins gated.

## Configuration and upgrade

`deferItemModelBaking`, `deferBlockStateModelBaking`,
`skipBlockStateGraphLoading` and `deduplicateResourceLocationNamespaces` are
default-on in 1.1.0. `parallelAtlasStitching` stays default-off; Forge's
texture-stitch event callbacks need ordered delivery. Compare Mode remains
available to isolate optimizations while retaining timers.

Close Minecraft, disable or remove the older VH Accelerator JAR, install the
1.1.0 JAR, and allow the first launch to refresh certified caches. Existing
LaunchFaster, Lightspeed and VHClientOptimize installations should remain
disabled because they overlap VHA's loading paths. No manual cache deletion
is expected.

- Clean Gradle build, tests, pinned Vault/JEI compatibility compilation, mixin

- Remastered, Wolds 0.34.1 and custom Vault client testing: recorded during
