# VH Accelerator 1.0.14

Release date: 2026-09-20

VH Accelerator 1.0.14 is a major performance, correctness, and maintainability release. It expands the mod's guarded Forge and Minecraft 1.18.2 optimizations, strengthens cache invalidation and cross-version safety, lowers disabled-diagnostic overhead, and keeps render-specific work in Vault Render Optimization.

## Download

```text
VH-Accelerator-1.0.14.jar
```

Do not install the `-sources.jar` as a mod.

## Compatibility

| Component | Supported version or change |
| --- | --- |
| Minecraft | 1.18.2 |
| Forge | 40.3.11 or newer in the Forge 40.x line |
| Vault Hunters Remastered | `20.0.3-remastered.6872` and `.6883` |
| Vault Hunters official | `3.21.5.6882` and `3.21.6.6884` |
| Custom MVP | `3.21.62` |
| Wolds Vaults | 0.32.2 (`3.21.5.6573`) and 0.33.0 (`3.21.6.6884`) |
| JEI | 9.7.2.1001, 10.2.1.1006, and 10.2.1.1009 |
| ModernFix | Optional; overlapping features are detected and handed to one owner |

These are tested baselines rather than hard dependencies. The release remains client-focused; dedicated-server support has not yet been declared or published.

## Highlights

- Added a guarded ModernFix backport framework with explicit ownership decisions, side checks, Compare Mode handling, configuration, and `/vha backports` diagnostics.
- Added or refreshed safe optimizations for Forge registry work, immutable resource-pack and ZIP indexes, language storage, recipe ingredients, object-holder cleanup, capabilities, loot resources, block states, world generation, chunk ticking, and allocation-heavy runtime paths.
- Strengthened model, blockstate, material, recipe, fuel, JEI, and asset cache invalidation across synchronized tags, config reloads, mod-folder noise, changing registry keys, embedded mod resources, and interrupted cache construction.
- Separated ordered disk work, CPU preparation, and optional network work to reduce contention on launch-critical workers.
- Omitted diagnostic-only mixins during bootstrap when debug mode is disabled, reducing normal-play instrumentation overhead.
- Added a version-guarded Target Dummy `1.18-1.5.2` correction that queues dispenser registration onto Forge's synchronous setup work.
- Moved ModernFix-derived render backports into Vault Render Optimization, leaving VHA focused on launch, login, caching, and non-render runtime work.

## Correctness and safety

- Connection state is now tied to the active network connection instead of transient loading screens, preserving valid state across dimensions and cluster transfers while rejecting stale callbacks.
- JEI runtime generations prevent old asynchronous work from publishing into a restarted runtime.
- Resource indexes accept immutable Forge and JarJar resource roots while retaining safe fallbacks for mutable, exploded, mixed, incomplete, or malformed sources.
- Recipe dependency fingerprints wait for synchronized tags and invalidate selectively when relevant configs or resources change.
- Model caches preserve dynamic-loader, registry mutation, metadata, and slot-texture safeguards.
- ModernFix ownership probes avoid loading game classes and fail closed when compatibility cannot be proven.

## Performance work

- Reused immutable material snapshots with session-local overlays and reduced repeated model-name parsing.
- Sized model maps from discovery results at the phase where the capacity is known.
- Reused pass-local Forge object-holder override metadata and short-circuited holders that cannot be removed.
- Added allocation reductions for wall shapes, potential spawn lists, ticking chunks, structure references, property names, resource keys, registry delegates, and selected world-generation paths.
- Added compact, reload-safe language and ingredient storage paths plus optional/default-off experiments where runtime evidence is still being gathered.
- Preserved full logical-processor availability for VHA's shared worker budget after testing showed the half-CPU limit could regress fast systems.

## Configuration and commands

- Added `/vha backports` to report active ownership and explain disabled or unavailable ModernFix-derived features.
- `/vha debug on|off` still saves the setting immediately; restart to load or unload the complete diagnostic-only mixin set.
- Added restart-only comparison toggles for staged model sizing, material cache sessions, isolated network work, Target Dummy setup deferral, and streamlined object-holder cleanup.
- Experimental or higher-risk paths remain default-off where the current evidence does not justify enabling them universally.

## Cache and migration notes

- Relevant persistent cache schemas and fingerprints invalidate automatically.
- The first launch or login after updating may rebuild affected caches once.
- No manual cache deletion or config migration is required.

## Upgrade instructions

1. Close Minecraft.
2. Disable or remove the older VH Accelerator JAR.
3. Install `VH-Accelerator-1.0.14.jar`.
4. Keep LaunchFaster, Lightspeed, and VHClientOptimize disabled because their loading changes overlap VHA.
5. Launch once to create or refresh cold caches, then judge normal performance on later warm launches and connections.
