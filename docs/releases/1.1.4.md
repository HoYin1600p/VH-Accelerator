# VH Accelerator 1.1.4

A maintenance release. Nothing changes in how the mod behaves, what it caches
or what its settings do, and your existing settings carry over.

## Download and compatibility

The release artifact is `VH-Accelerator-1.1.4.jar` for Minecraft 1.18.2 and
Forge 40.3.11 or later in the Forge 40.x line. Compatibility is unchanged from
[1.1.3](1.1.3.md). The optional settings screen still needs
[Cloth Config](https://www.curseforge.com/minecraft/mc-mods/cloth-config)
6.5.102 or newer. Do not install a sources JAR.

## Changed

- **Translatable messages.** The launch, server/world transfer and
  post-login timers, the JEI rebuild messages and the update notice now come
  from the language file, so they can be translated. The English text is
  word-for-word the same. Replies to `/vha` commands sent by a server stay in
  plain English, so players without VH Accelerator never see raw keys.
- **Mods list.** VH Accelerator now shows its logo and a fuller description.
- **Logging.** A failure inside a Vault Hunters event listener is now written
  to `latest.log` instead of only the console.
- **Reproducible builds.** The same source now always produces a byte-identical
  jar.

## Internal

The code was reorganised and tidied: a clearer package layout with no
dependency cycles, smaller classes in place of the largest ones (the mixin
plugin, the client config and the asset fingerprint), shared helpers instead of
copies, and one safe-write path for the caches. Tests recorded from 1.1.3
prove that every mixin decision, the generated config files and the asset
fingerprint are unchanged. Contributors can find the layout in
[ARCHITECTURE.md](../ARCHITECTURE.md).

Caches rebuild once on the first launch, as after any update.
