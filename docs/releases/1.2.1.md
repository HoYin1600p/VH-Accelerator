# VH Accelerator 1.2.1

Release date: 2026-11-27

VH Accelerator 1.2.1 keeps full compatibility with The Vault 22.0.0 (`7152`, `7209`), 3.22.0 (`7210`), and 22.0.1 (`7237`), stops Xaero's Minimap and World Map update notices from blocking the title screen, hardens KubeJS/CraftTweaker parallel recipe handling and the experimental `BlockState` lazy cache against concurrency edge cases, and backports three November 2026 ModernFix optimizations for Forge 1.18.2.

## Download and compatibility

The release artifact is `VH-Accelerator-1.2.1.jar` for Minecraft 1.18.2 and Forge 40.3.11 or later in the Forge 40.x line, with Java 17-compatible bytecode. Use the same universal jar on clients and dedicated servers. The in-game settings screen requires Cloth Config for Forge 6.5.102 or newer (optional; the mod runs normally without it). Do not install the `-sources.jar` as a mod.

## Detailed changes since v1.2.0 (`v1.2.0...v1.2.1`)

### Added

1. **Xaero update-notice suppression (`compatibility.suppressXaeroUpdateScreen`, client, default `true`, restart required):**
   - Prevents Xaero's Minimap and World Map from replacing the title screen with an update prompt on Vault Hunters packs (which pin Xaero versions).
   - While enabled, VHA treats Xaero's "allow internet access" option as off (skipping online version and Patreon checks without modifying Xaero's config file) and suppresses the update screen itself.
   - Applies even when VHA's optimization masters are off because it is a compatibility fix. Note that Xaero Patreon supporter perks do not load while this setting is active.
2. **November 2026 ModernFix backports (LGPL-3.0-or-later, all default `true`, restart required, yield to ModernFix & Compare Mode):**
   - **Faster server biome lookups (`backports.fasterBiomeLookups`, common, ModernFix `20e048f9`):** Overrides `ServerLevel.getNoiseBiome` to read directly from already-loaded `FULL` chunks via `ServerChunkCache.getChunkNow` before falling back to `ChunkStatus.BIOMES` and `getUncachedNoiseBiome`. Avoids exact-status cache misses on loaded chunks during server biome queries.
   - **Cached Architectury event invokers (`backports.cacheArchitecturyEventInvokers`, common, ModernFix `0ce7f03c`):** `@Pseudo` mixin on `dev.architectury.event.EventFactory.invokeMethod` backed by `ArchitecturyEventInvokers`, caching adapted `MethodHandle` invokers in a `ConcurrentHashMap<Method, MethodHandle>` instead of unreflecting and adapting a fresh handle on every dynamic proxy listener call. Gated on Architectury presence and verified against both `4.11.93` and `4.12.94`.
   - **Shared OSHI `SystemInfo` (`backports.shareOshiSystemInfo`, common & client, ModernFix `64ce25a1`):** Redirects `new oshi.SystemInfo()` in `SystemReport` and client `GLX._init` to `SharedSystemInfo.get()`, reusing one lazily initialized `SystemInfo` instance and avoiding redundant OS/WMI hardware probes at startup and during crash/debug reports.

### Changed (Vault Hunters 22.0.x upstream-fix handoffs)

All Vault handoffs inspect the live target classes rather than matching mod version strings, so older Vault builds automatically keep every VHA optimization while newer Vault builds run Vault's own implementation without duplicate hooks:

- **Vault 22.0.0 build 7152 / 7209 & 3.22.0 build 7210:**
  - `snapshotVaultEventListeners` stays off when Vault ships its own event listener cache.
  - `lazyCompactVaultLootCdf` and `optimizeVaultLootCdf` stay off when Vault replaces `TieredLootTableGenerator.CDF` with `TieredLootRarityTables`.
- **Vault 22.0.1 build 7237:**
  - Cascade modifier stack indexing (`optimizeVaultCascadeModifiers`) stays off when Vault ships `Modifiers$StackIndex` / `stacksOf()`.
  - Empty-`ItemStack` entity-reference cleanup stays off when Vault ships `MixinItemStack.keepEmptyStacksFreeOfEntityLinks`.
- Every other Vault compatibility hook remains active across all supported Vault builds.

### Fixed (KubeJS, CraftTweaker, and `BlockState` concurrency/compatibility)

- **KubeJS parallel recipe filters (`optimizations.parallelKubeJsRecipeFilters`):**
  - Restricted parallel pre-filtering strictly to KubeJS's own internal consumers (`remove` and `stage`), keeping script `forEachRecipe` callbacks sequential.
  - Recursively inspects `Map` entries and `Object[]` arrays in `KubeJsParallelFilters` so map-backed or nested custom filters are never assumed worker-safe.
  - Falls back to sequential evaluation for ID and mod filters whenever any recipe has a `null` ID, avoiding concurrent races inside KubeJS's unsynchronized MD5 helper (`UtilsJS.getUniqueId()`).
  - Falls back to sequential evaluation for input/output filters when KubeJS's `useOriginalRecipeForFilters` option is enabled so modded `Recipe` implementations are never invoked off-thread.
  - Warms lazy `ItemStackJS.getList()` and `TagIngredientJS.getHolders()` caches on the calling thread before worker fan-out.
- **KubeJS JEI hiding (`HideJEIEventJSMixin`):** Restricted fast-path matching to KubeJS's own JEI item-matcher lambda so custom script hide predicates stay untouched, and pre-warms ingredient caches on the calling thread.
- **KubeJS resource-pack existence cache (`KubeJSResourcePackExistsMixin`):** Resolves `KubeJSPaths.DIRECTORY` first (falling back to `gameDirectory/kubejs`) and avoids caching an empty directory snapshot before the pack folder exists.
- **CraftTweaker parallel recipe removal (`optimizations.parallelCraftTweakerRecipeRemoval`):** Keeps `ActionRemoveRecipeByOutputInput` on the calling thread so modded `Recipe.getIngredients()` and vanilla `Ingredient.dissolve()` are not invoked concurrently across worker threads.
- **Experimental `BlockState` lazy cache (`BlockStateMixin`):** Defers clearing the deferred-cache flag until `initCache()` finishes, using a per-instance initializing-thread guard so concurrent readers cannot observe a half-initialized cache.

## Upgrade

Back up your configs and world, stop Minecraft / your server, replace the older `VH-Accelerator-*.jar` with `VH-Accelerator-1.2.1.jar` (keeping only one VHA jar in `mods`), and launch. Existing settings carry over automatically.
