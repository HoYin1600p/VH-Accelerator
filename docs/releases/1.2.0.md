# VH Accelerator 1.2.0

Release date: 2026-10-28

1.2.0 is the first VH Accelerator release built for dedicated servers as well as
clients. It cuts server startup time and memory in the tested packs, fixes several
startup races that could crash or hang a server, and adds an operator-only
**Server** tab to the settings screen. It also includes the client fixes and the
model bakery API prepared for 1.1.5, which was never published on its own.

## Download and compatibility

The release artifact is `VH-Accelerator-1.2.0.jar` for Minecraft 1.18.2 and
Forge 40.3.11 or later in the Forge 40.x line, with Java 17-compatible bytecode.
Use the same universal jar on clients and dedicated servers. Each optional integration
still requires its reviewed mod version and class layout. The settings screen needs
Cloth Config for Forge 6.5.102 or newer; the mod works without that screen dependency.
Do not install the sources jar as a mod.

## Dedicated-server results

In paired startup tests against **no VHA jar**, median time from JVM start to Minecraft’s “Done” fell from **40.77 to 30.86 seconds on a large production server pack**, and **54.84 to 36.92 seconds on Wolds Vaults 0.34.3**. Median live heap fell from **5,630 to 3,436 MB**, and **1,696 to 1,305 MB**, respectively.

These are three counterbalanced pairs per pack, booting one test server at a time, with memory sampled 90 seconds after startup. The production pack test used a copy of a live server's world with Vault 3.21.62/VHAPI 5.0.0; Wolds 0.34.3 used a fresh empty world with Vault 3.21.6.6884/VHAPI 5.8.1. Reported median paired improvements were **24.4% startup / 38.8% heap** on the production pack and **32.1% / 23.2%** on Wolds. These measurements used the earlier test feature set; later additions have separate checks. They are test-pack results, not a promise for every server.

Before release, 1.2.0 ran on five live Vault Hunters servers through many restarts with no crashes and no VH Accelerator warnings or errors. Heap use in the first 15 minutes after the daily restart was 41–68% lower than the same window the day before. That is an observation from live servers, not a controlled test.

## Stability fixes

- Protects startup registry writes and Forge holder creation from races that could cause crashes, missing holders or corrupt registrations.
- Fixes a reload-barrier race that could leave startup waiting forever, and protects EventBus’s generated-listener cache during parallel mod construction.
- Prevents budding crystal growth from reading unloaded neighbouring chunks during chunk loading.
- Keeps startup-report failures from stopping the game, and corrects optional mixin handlers that could otherwise fail to apply. Builds now check handler compatibility against real target classes.

## Memory and loading changes

- Vault loot distributions are calculated when first needed and stored compactly, including with supported VHAPI versions. Separate paired tests saved about **127–138 MB**. Large tested tables took **33–42 ms once on first use**; repeated bulk rolls matched the control.
- BuildingGadgets templates use compact positions; a separate production-pack comparison measured about **637 MB less live heap**. WorldZones uses smaller single-zone memberships, saving about **101 MB** in its paired production-pack test, with matching saves and restart results.
- Equal AE2Things disk-data strings are shared; block-state serialization codecs are built on demand; finished Mixin class trees are stored as compressed bytes. Codec and string-sharing savings depend on the pack and data; their offline estimates are not additional measured whole-server savings.
- Registry lookups use an ordered index that is released after loading. Block-state ID tables start at the required size. Supported KubeJS/CraftTweaker recipe removals use indexes, LootJS regex checks stop once a match is found, and safe KubeJS filters can run in parallel. Recipe comparisons matched before and after reload.
- Dedicated servers now use the launch shape cache and coordinate-merging improvements. Resource-index preparation and scan-data compaction use shared workers. Thermal’s JEI-only converted-fuel lists are built on demand; dynamo fuel acceptance is unchanged.

## Client fixes and additions (prepared for 1.1.5)

- Framed drawers and similar blocks no longer show the missing texture when deferred item model baking is on. Deferred item models can now be baked safely on chunk-build threads.
- The Vault cascade filter works again on Vault Hunters 21.6, which moved the cascade scan into a new method used by both cake generation modes and Greed vaults. The new hook has its own setting, `filterVaultCascadeChunk` (default on, no restart needed). Older Vault builds keep the original hook.
- The cascade filter now keeps the order in which Vault visits the remaining block entities, so overlapping cascade placements end the same way as in Vault's own run.
- Mod developers can use a new optional model bakery compatibility API (`ModelBakeryEvents`, API version 1) to supply native models and blockstates through VHA, including JSON kept in binary resource bundles. BuildScape is the first user. Contributed by KyroXova. See [Compatibility.md](../../Compatibility.md).
- Every build dependency now comes from CurseMaven, so the mod builds from a clean clone.

## Settings

The in-game settings screen now has a **Server** tab for operator-level-4 players.
It reads and saves the connected server's common settings through a server-authoritative
channel, with permission, key, type and range checks on every request. Server defaults,
Experimental actions and restart notices are separate from local client changes.
The channel is optional: missing or unsupported peers keep normal gameplay and show
an explanation instead of server controls. Integrated servers use the same permission
checks. Startup-bound server changes need a server restart; integrated-server changes
need Minecraft to restart.

Relevant new or newly server-enabled common settings are below. **All default to `true`** unless stated otherwise; exact mod/version/layout guards still decide whether each feature can run.

| Section | Keys |
| --- | --- |
| `backports` | `reloadBarrierRaceFix`, `registryWriteConcurrencyFix`, `eventBusWrapperCacheConcurrencyFix` |
| `compatibility` | `fixBuddingCrystalChunkLoad`, `lazyCompactVaultLootCdf`, `optimizeVaultLootCdf`, `compactBuildingGadgetsTemplates`, `compactWorldZonesMemberships`, `shareAe2ThingsDiskStrings`, `shortCircuitLootJsRegexFilters`, `deferThermalConvertedFuels` |
| `optimizations` | `indexObjectHolderDispatch`, `presizeBlockStateIdMap`, `lazyBlockStatePropertyCodecs`, `releaseMixinClassTrees`, `indexKubeJsRecipeRemovals`, `indexCraftTweakerRecipeRemovals`, `parallelKubeJsRecipeFilters`, `cacheLaunchVoxelShapes`, `optimizeVoxelShapeMerging` |

Most of these settings require a restart; consult the configuration guide for live-setting exceptions. Existing resource-index and scan-data settings remain in use. Optional startup recording, `diagnostics.startupJfr`, defaults to **`false`**. Operators can use `/vha dump blockshape` for diagnostic exports.

Defaults revision **4** enables Mixin class-tree release once for older configurations; revision 3’s WorldZones upgrade remains in place. An old explicit `false` cannot be distinguished from the previous generated default, so it also changes once. Set it back to `false` after upgrading to keep an opt-out; later opt-outs and previously applied revisions are preserved. Missing keys use the current defaults. The Experimental button preserves these opt-outs.

## Upgrade notes and limits

Update Wolds Vaults to a release containing [upstream PR #260](https://github.com/iwolfking/Wolds-Vaults-Official-Mod/pull/260). VHA’s Rampage startup workaround and its setting have been removed; older unfixed Wolds versions retain that upstream race.

Java 24+ may print a one-time `sun.misc.Unsafe` deprecation warning from the guarded EventBus cache fix. VHA adds no warning-suppression flags; unavailable access retains the original cache with a warning.

The copied production-pack runtime tests held 20 TPS, with median/p95 active tick times within about 1 ms. More reported intervals just over 50 ms reflected tighter tick pacing, not a demonstrated processing slowdown; GC pauses and sampling also affected the tail. No general gameplay FPS, loaded-server TPS or reload-speed gain is claimed. Unsupported layouts keep their original paths. Feature-specific savings overlap with the headline totals and must not be added together.

## Upgrade

Back up your configs and world, replace the older VHA jar, and inspect the compatibility
summary after launch. Existing settings carry over except for the one-time defaults
upgrades described above. See [Configuration](../CONFIGURATION.md) for restart requirements
and [Installation](../INSTALLATION.md) for deployment and rollback instructions.
