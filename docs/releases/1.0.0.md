# VH Accelerator 1.0.0

Release date: July 28, 2026

VH Accelerator 1.0.0 is the initial public release of the Forge 1.18.2 launch
and multiplayer world-entry optimizer.

## Download

Install the non-sources artifact:

```text
VH-Accelerator-1.0.0.jar
```

Do not install the `-sources.jar` as a mod.

## Supported baseline

| Component | Version |
| --- | --- |
| Minecraft | `1.18.2` |
| Forge | `40.3.11+`, below Forge 41 |
| Java bytecode | 17 |
| Vault Hunters Remastered | `20.0.3-remastered.6872` |
| Vault Hunters official | `3.21.5.6882`, `3.21.6.6884` |
| Custom MVP | `3.21.62` |
| JEI | `9.7.2.1001`, `10.2.1.1009` |

The Vault and JEI versions are guarded compatibility baselines, not mandatory
dependencies. The mod can load without either project.

## Release highlights

### Faster client launch

- Reads and parses eligible plain model JSON concurrently.
- Prepares independent blockstate and canonical model-key data in overlapping
  pipelines.
- Prepares eligible texture atlases and top-level models in bounded batches.
- Builds the final block render lookup in worker-owned ranges after ordered
  Forge callbacks complete.
- Indexes immutable jar-backed resources.
- Persists only deterministic raw model/blockstate data and material
  identifiers behind exact client-asset fingerprints.
- Defers validated Xaero network checks and initial Vault GUI atlas upload work
  beyond the critical reload phase without exposing incomplete state.

### Faster server login and cluster transfers

- Builds JEI's search index as an unpublished worker-owned object and performs
  one client-thread publication.
- Populates independent JEI search prefixes concurrently.
- Validates vanilla JEI recipe groups concurrently while preserving result
  order.
- Persists validated JEI item and recipe-index data for repeat connections.
- Uses targeted caches and indexed lookups for Powah, JEITweaker, JER,
  CraftTweaker, Thermal, Iron Furnaces, and Industrial Foregoing.
- Stages Vault group construction with a bounded client-tick budget.
- Rejects stale post-login work after a rapid transfer or disconnect.

### Dynamic-model safety

- Detects custom geometry and dynamic model graphs.
- Keeps protected graphs on Forge's original sequential path.
- Retries the complete top-level bake sequentially after a worker failure.
- Never serializes baked models, textures, custom geometry, or runtime block
  entity state.
- Explicitly protects the dynamic behavior used by Vault gear, Sophisticated
  Storage, Every Compat, and BuildScape test cases.

### Measurement and control

- Displays client launch time on the menu.
- Reports multiplayer login, server/world transfer, post-login completion, and
  disconnect time.
- Reports dedicated-server launch time when installed on a server.
- Adds Compare Mode, which disables every optimization while retaining
  selected timers and diagnostics.
- Keeps visible timers on by default and detailed debug diagnostics off by
  default.

Complete command list:

```text
/vha
/vha compare
/vha compare on
/vha compare off
/vha compare status
/vha timers
/vha timers on
/vha timers off
/vha timers status
/vha debug
/vha debug on
/vha debug off
/vha debug status
```

See [Configuration and commands](../CONFIGURATION.md) for behavior and
permissions.

## Installation

1. Disable LaunchFaster, Lightspeed, and VHClientOptimize.
2. Place `VH-Accelerator-1.0.0.jar` in the client `mods` directory.
3. Keep the generated defaults for the first stability run.
4. Launch once to create validated cold caches.
5. Launch and connect again to measure warm behavior.

ModernFix is optional and supported. VH Accelerator yields transformations
that ModernFix already owns.

See [Installation](../INSTALLATION.md) for client-only and dedicated-server
deployment.

## Default diagnostics

```toml
[diagnostics]
compareMode = false
timers = true
debug = false
```

The timer setting can be changed immediately with `/vha timers on|off`.
Detailed debugging is available with `/vha debug on` but is not intended for
normal play.

## Server-side status

The 1.0.0 jar is dedicated-server safe and contains:

- dedicated-server launch timing;
- immutable jar-resource indexing;
- conservative common resource-list caching;
- experimental common switches that remain off by default.

Full server startup optimization is not claimed in this release. Future
versions can append server work under the dedicated `### Server` changelog
category and the `Server-side changes` section in the release-note template.
Likely research areas include Vault configuration and individual datapack
reload listeners.

## Known limitations

- Only Minecraft 1.18.2 and Forge 40.x are supported.
- A cold launch or first connection must build or validate cache data before a
  later run can reuse it.
- Dynamic/custom models intentionally receive less parallel work.
- Server login includes remote network and server tick delay; compare several
  samples.
- The persistent vanilla recipe-validation cache is disabled because its
  fingerprint can cost more than parallel revalidation.
- Experimental registry-validation and BlockState switches are implemented
  for research but disabled by default.

## Verification performed

- Verified both JEI compatibility generations are present in one jar without
  bundling dependencies.

- Cluster server/world transfer and rapid-transfer safety tests.
- Disconnect during post-login work.
- Visual inspection of Vault gear and GUI atlases, Sophisticated Storage,
